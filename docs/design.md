# ペアマネ 設計書

このファイルが設計の正本です。以前claude.ai上で作った「ふたり精算アプリ 設計書」は初期の検討用で、内容が古くなっています。

## 1. 目的と範囲

- 同棲するふたりが、立て替えた支出を記録し、決めた負担割合で精算するためのアプリ。
- 参考にしたアプリ: App Storeの「とんとん」。無料版の件数制限やサブスクを避けるために自作した。
- 一般公開はしない。ふたりだけで使う。

### やらないと決めたこと

| 機能 | 理由 |
|---|---|
| レシートOCR | 精度の確認と修正の手間が、金額を手入力する手間と変わらないため |
| スマホへのプッシュ通知 | Cloud Functions が必要で、Firebaseの有料プラン（Blaze）が必要になるため。ユーザーが有料プランを望まなかった。代わりにアプリ内通知を実装 |
| App Storeでの公開 | ふたり専用のため。PWAとしてホーム画面に追加して使う |

## 2. 計算ロジック

すべて円の整数で扱う。

| 記号 | 意味 |
|---|---|
| T | 支払総額 |
| P | 払った人 |
| O | 払っていない人 |
| k_P, k_O | それぞれの個人負担（割り勘しない分） |
| r_O | 払っていない人の割合（%） |

```
S   = T − k_P − k_O              （割り勘する部分）
B_O = floor(S × r_O / 100) + k_O （払っていない人の負担。端数は切り捨て）
B_P = T − B_O                    （払った人の負担）
```

- 端数は「払っていない人の負担を切り捨て」。とんとんの実機の結果と一致する（1,001円・70:30 → 300円、1,005円 → 301円 / 704円）。
- 分け方（`method`）
  - `ratio`: 割合。支出ごとに `ratioA`（a の%）を持つ。初期値は設定の基本割合
  - `amount`: a の負担額 `amtA` を直接指定し、残りは b
  - `all_a` / `all_b`: どちらかが全額負担
- 払っていない人が払った人に渡す額 = B_O。

### 集計

| 項目 | 対象 |
|---|---|
| 精算残高 | 未精算、かつ有効な支出（あとで精算は反映日以降）の B_O を、払った人ごとに相殺した差額 |
| 立替状況 | 同じ条件で、払った人ごとの B_O の合計 |
| 確定待ち | あとで精算で、反映日前のもの。精算残高には入らない |
| レポートの合計 | その月のすべての支出（精算済み・確定待ちを含む） |
| レポートの負担額 | その月の支出の B_P / B_O を、人ごとに合計 |

### あとで精算

- `pending: true` と反映日 `reflect`（初期値は翌月1日）。`reflect <= 今日` になると有効になる。

### 精算の確定

- 有効な未精算の支出をすべて `settled: true` にし、`settlements` に1件追加（from → to、金額、日付）。確定待ちの支出は残す。
- 確定後は全画面の「精算完了」表示を約1.2秒出す。

### 固定費

- `fixedCosts` に、金額・毎月の日（1〜31、月末を超える日はその月の末日）・払う人・カテゴリ・名前を持つ。
- アプリを開いたときと、前面に戻ったときに確認する。今月の指定日を過ぎていて、`lastYm` が今月でなければ、支出を作成し、`lastYm` を今月にする。この2つは同じバッチで書く。
- 支出のIDは `固定費ID_YYYYMM`。ふたりの端末が同時に作っても重複しない。
- 新しく登録した月は、指定日がすでに過ぎていれば翌月から始める。
- 割合は登録時点の基本割合を使い、`by: 'x'`（自動）として通知の対象外にする。

## 3. データモデル（Firestore）

```
couples/{cid}                     cid はランダム20文字
  memberUids: [uidA, uidB]        0番目 = a(作成した人)、1番目 = b(参加した人)
  members: {a: {name, photo}, b: {name, photo}}   photo は192pxのJPEG dataURL
  ratioA: 70                      基本の負担割合（a の%）
  inviteCode: "K7Q4M2XD"          パートナー参加前のみ
  cats: [{id, name, icon, color}] 追加カテゴリ（id は "c..."）
  budgets: {catId: 円}            月の予算
  createdAt

couples/{cid}/expenses/{id}
  id, date(YYYY-MM-DD), amount, payer('a'|'b'), cat, memo,
  method, ratioA, amtA, kA, kB, pending, reflect, settled,
  by('a'|'b'|'x'), at(ms)         by/at は通知用

couples/{cid}/settlements/{id}    id, date, from, to, amount
couples/{cid}/fixedCosts/{id}     id, cat, memo, amount, day, payer, lastYm
couples/{cid}/notes/{id}          id, text, by, at, done（要望メモ）
couples/{cid}/shopping/{id}       id, name, key(正規化した名前), cat, memo, by, at, done,
                                  doneAt(ms), doneBy, doneDate, expensed（買い物リスト）
couples/{cid}/shopStats/{id}      id(key のハッシュ), key, name, cat, dates(直近10回の購入日), count, lastAt

invites/{code}                    {cid, createdAt}。コード → カップルの対応
```

- 標準カテゴリは8つで、コードに固定（`food 食費`、`daily 日用品`、`eat 外食`、`trip 旅行`、`rent 家賃`、`util 光熱費`、`fun 娯楽`、`other その他`）。追加カテゴリは「その他」の前に並ぶ。削除したカテゴリの支出は「その他」として表示する。
- 端末ごとの設定は localStorage に置く: `pairmane.cid`（接続先）、`pairmane.seen`（通知の既読時刻）、`pairmane.theme`、`pairmane.font`。

### 読み込む範囲（無料枠の節約）

- 支出は2つの購読に分ける: ①先月1日以降の支出、②未精算の支出（月を問わず）。精算残高・確定待ち・予算・通知はこの2つで足りる。
- 先月より前の月は、履歴・レポートで「この月のデータを読み込む」を押したときに1回だけ読む（`loadMonths`）。読み込んだ月は `EXP.extra` に持ち、編集・削除・精算のときに手元のコピーも直す。
- レポートの6か月推移は、読み込んでいない月を点線の棒で表示し、「過去6か月分を読み込む」で補う。
- バックアップと全削除は、押したときに全件を読み込む。
- 月をまたいでアプリを開いたままの場合は、前面に戻ったときに購読を張り直す。

### レポートの絞り込み

- 「ふたり／a／b」の切り替え（端末の `pairmane.repP`）。人を選ぶと、合計・内訳・6か月推移を、その人の負担額 `calc(e)[a|b]` で集計する。予算の表示は、ふたりの合計で見るものなので出さない。

- レポート上部にその月のカテゴリを並べ、押すと集計から外す。外したカテゴリは端末の `pairmane.repEx` に保存する。
- 合計・ふたりの負担額・内訳・6か月推移に反映する。精算の金額や予算の表示には影響しない。
- 一時的な大きな支出（引っ越しの初期費用など）は、専用のカテゴリを作って外す運用を想定。

### 買い物リスト

- 購読は ①未購入（`done == false`）、②今月・先月に購入（`doneDate >= 先月1日`）、③`shopStats` 全件。それより前に買ったものは「〇月に買ったものを読み込む」で1か月ずつ読む（`loadOlderShop`）。
- 丸を押すと `done:true` と購入日を記録し、`shopStats` の `dates` に今日を足す（同じ日は1回、直近10回まで）。戻すと取り消す。
- 周期: 購入日が2回以上ある品目は、(最後 − 最初) ÷ (回数 − 1) を平均日数とし、前回からの経過日数が平均の85%以上で「そろそろ買う時期」に出す。
- 「支出に記録」: 今日買って、まだ記録していない品目の名前をメモに入れ、いちばん多いカテゴリを選んだ状態で支出の追加画面を開く。保存すると、その品目に `expensed:true` を付ける。
- ルールが未公開でも他の機能は動く（買い物タブに「ルールの更新が必要」と出る）。

## 4. ログインと接続

1. 「新しく始める」か「招待コードで参加」を押したときに、はじめて匿名ログインする（Firebase Auth）。ページを開いただけ（検索エンジンやリンクのプレビューを含む）ではアカウントを作らない。
2. 「新しく始める」: `couples` と `invites/{8文字コード}` を作る。コードは紛らわしい文字を除いた32文字種から8文字（約1兆通り）。
3. 「招待コードで参加」: `invites/{code}` を読んで cid を得て、`memberUids` に自分を追加する。参加後に招待コードは削除する。
4. 起動時は `pairmane.cid` を使い、なければ `memberUids array-contains uid` で検索する。
5. 引き継ぎ用アカウント: 匿名アカウントに、メール＋パスワードを `linkWithCredential` で紐づける（uid は変わらない）。別の端末では `signInWithEmailAndPassword` で同じ uid に戻る。

## 5. セキュリティ（firestore.rules）

- カップルのドキュメントと配下は、`memberUids` に入っている人だけが読み書きできる。
- 参加は、席が1つ空いているときだけ、自分を `memberUids` の末尾に足す変更だけを許可する。
- `invites` は1件ずつの取得のみ。一覧は取得できない。
- 支出・精算・固定費・メモは、フィールド名・型・金額の範囲を検証する。
- 残っているリスク: 招待コードを作ってからパートナーが参加するまでの間に、コードを知った第三者が先に参加できる。コードはふたりの間だけで送る。

## 6. 画面

ホーム / 買い物 / レポート / 履歴 / 設定 の5タブと、追加・編集、精算、固定費、カテゴリと予算、要望メモ、使い方のシート。

- ロゴ: 「にっこりコイン」。`index.html` の `LOGO_MARK`（SVG）と `logoHTML()`。アイコンは同じ絵を淡いラベンダー（#e8edff）の背景に置いたもの
- 配色: インディゴ（#3b5bdb）が基調。a＝青（#4c6ef5）、b＝ピンク（#f06595）。ダークテーマあり
- フォント: Zen Maru Gothic（ゆったり）、Noto Sans JP（すっきり）、Shippori Mincho（しっとり）
